# HEURIAL Studio — project instructions

Durable rules. Current status lives in `HANDOFF.md`.

## Where to work
- Work in `~/heurial-dev/heurial-design`, never in iCloud Documents (iCloud offloads `node_modules`).
- The iCloud copy under `Documents/Codex/.../outputs/heurial` is ChatGPT's old checkout. Don't edit it or deploy from it.
- Git in this worktree can time out because its data lives in the Documents repo `.git`. Retry.
- `AGENTS.md` is generated by `next dev`. Leave it alone.

## Git
- One branch per task. Push the branch, then wait for the user to say "Yes, merge it".
- To merge: check `git ls-remote origin main` first, merge main into the branch if it moved, then fast-forward.
- No force pushes or history rewrites without asking.
- Never deploy without an explicit go-ahead. Before deploying, state the exact commit and destination.

## Catalyst and deploys (Claude handles these since 2026-11-13)
- Access: the Catalyst CLI (signed in as the owner) and the "Catalyst by Zoho" connector. Project Project-Rainfall,
  org 946299681. Link files (`.catalystrc`, `catalyst.json`, `catalyst/.catalystrc`, `catalyst/catalyst.json`,
  `.catalyst/`) are gitignored and live only in this folder.
- The CLI can hang on prompts. Run it with a time limit (`perl -e 'alarm 120; exec @ARGV' catalyst ...`) and pass
  `-ni` where it helps.
- Functions: run from `catalyst/` (its `catalyst.json` lists the functions): `catalyst deploy --only
  functions:pipeline,functions:inquiries` goes to **Development**. Production gets functions, tables, job schedules
  and their settings only through a console deployment (Production is read-only; API writes to it are refused).
- Console deployment (worked 2026-11-13; the owner signs in to the browser pane, Claude clicks): Development →
  Settings (gear) → Environments → Deployments → **Create Deployment**. Commit message max 40 characters. Select the
  services, then **Generate Diff** (takes 1-3 minutes; reload the list to see `Diff_Completed`), open the row and read
  every service's counts before **Initiate Deployment** → **Yes, Proceed**. A draft made before the latest
  Development change shows 0 function changes: abort it and create a new one. Job Scheduling can only be selected
  after its "Start Exploring" page has been opened once in Development. Slate is not part of these deployments.
  Schedules arrive switched off if they were off in Development; switch them on in Production → Job Scheduling → Cron.
- Website: the Slate app `heurial` has one live deployment (`heurial-mmoiyutd.onslate.com`, behind
  www.heurial.studio). `catalyst deploy slate heurial --production -m "<what> main <sha>" -ni`
  from the repo root replaces the live site directly (without `--production` it tries to create a new app and fails
  with 409). A build takes about 2 minutes. Deploy and promote functions first,
  then the site. The connector can list builds and roll back to the previous one.
- Deleting rows or creating anything in Production through the connector is blocked by Claude's safety checks;
  the owner deletes test rows (Data Store → table) or dismisses them in the tracker.
- Slate serves every file in `public/` with a one-year browser cache and ignores `next.config.ts` headers for them.
  Tracker files load with `?v=<fingerprint>` (computed in `next.config.ts`); add any new tracker file to
  `TRACKER_FILES` there and load it through `__load` in the HTML pages.
- Release steps: `git fetch`, `git switch --detach origin/main`, confirm a clean tree, run the checks, deploy,
  then check `/admin` and the function URLs (an unkeyed request should return `{"error":"Unauthorized"}`).
- Don't list function settings through the connector: the response includes secret values. Read settings by name
  only when needed, and never repeat them.

## Secrets
- Never put passwords, tokens or API keys in chat, git or logs.
- The user runs the password-hash script themselves.
- Never use the user's GitHub password.

## Copy and brand
- Brand is HEURIAL in capitals. Assets are in `public/brand/`. Never use the Curivis brand.
- Text is Inter Tight (`public/fonts/inter-tight-var.woff2`, the variable file: a single-weight file makes all bold text render regular, chosen 2026-11-13), numbers in sentences included. Standalone figures (prices, totals, counters) carry the `num` class and use Helvetica.
- Copy is first person, with no filler labels and honest claims. Demos are labelled sample data.
- Editorial look. The glass style was rejected as looking AI-made.

## Tracker
- One shared app: `public/tracker/tracker.js` + `tracker.css`, started with `HeurialTracker.start({mode, api, auth})`.
- `/admin` (`public/admin/index.html`) uses the real API. `/demo/tracker` uses an in-browser back end.
- `public/demo/tracker/core.js` is a browser copy of `catalyst/functions/pipeline/core.js`. Keep them in sync.
- Style matches its preview on the home page: the site's font and colours, flat dark panels, three small tiles, cards with a status dot. No glows or gradients. It must stay easy: text 14px or larger, controls 40px or taller.
- Overview leads with the money line: total earned, stepping up at each paid lead. Every figure and line comes from the leads themselves; nothing decorative.
- Setup for Catalyst tables and env vars: `catalyst/TRACKER-SETUP.md`.
